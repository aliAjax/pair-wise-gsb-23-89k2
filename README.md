# hxwl-09 半导体洁净室互锁门禁

人员、房间、物料、灭菌有效期与通行许可一体化联动的外门控制系统（前端规则引擎 + 断网门控模拟）。

## 技术栈

React 19 + Vite + TypeScript + CSS，状态自研（`useSyncExternalStore`），测试 Vitest。

```bash
npm install
npm run dev        # http://localhost:5109
npm test           # 14 条端到端规则测试
npm run typecheck
npm run build
```

## 规则模型（不再是静态示例）

外门判定统一走 `src/engine.ts` 的 `evaluate()`，阻挡原因统一字典
`BLOCK_REASONS`，**操作页与追溯记录渲染同一份文案与原因码**。

### 准入链路（同一入口按顺序判定）

1. 门控在线 / 许可存在且未吊销、未超时、未使用、无字段冲突
2. 规则或批次调整后许可处于 `reconfirm` → 重新确认通过前不能进入
3. 随行人员洁净资质有效
4. 每件物料：灭菌批次未作废、当前时间未超过「灭菌时间 + 有效期」→ 否则停在外门并写明物料/批次/到期时间
5. 通道实时压差 ≥ 压差规则下限 → 否则停在外门写明实测值与规则值
6. 通道存在未结异常 → 进入待处理队列
7. 同一互锁通道已有一组人员在内 → 进入待处理队列；离开释放互锁后按 FIFO 自动放行，一次只放一组
8. 已进入（used/exited）的许可再次刷卡一律拒绝，门不会再开

### 规则/批次版本指纹

许可签发时绑定 `RuleSignature`：压差规则 `version` + 各携带物料所属灭菌批次的 `revision`。

- 调整压差规则或灭菌批次（有效期、作废）→ 已签发且未使用的许可**立即变 reconfirm**，外门拒绝；
  重新确认通过（人员/物料/压差再校验）并重绑指纹后才能进入。
- 已在通道内的人员不受追溯影响；时钟推进后超时许可自动失效。

### 断网门控（`src/store.ts`）

- 门控离线时冻结最后同步的许可快照与判定上下文（人员资质/批次/规则/压差/异常），刷卡只在本地判定；
  本地流水（ENTER / EXIT / EDIT_NOTE / ENQUEUE，含 seq）存于门控，`usedPermitIds` 防止离线重复开门。
- 回传按门生成**批次**：链路失败保留进度，重试只补未确认（`ack=false`）的流水与未完成的门；
  已完成的门不再回传。
- 合并以许可编号为键：
  - ENTER 用当前中央数据复核，离线期间已失效/不合规的进入登记为通道异常（事实保留、阻断后续）；
    重复 ENTER 只记审计，不再开门；
  - 同一字段（备注）门控离线版与中央版都改过 → 两版都保留，许可挂 `conflict` 等班长裁决，裁决后恢复；
  - 离线排队事件回传补入中央队列。

## 页面板块

互锁通道（实时压差/占用/异常/门控在线状态）、灭菌批次与压差规则调整、许可签发、
许可操作页（实时复检 + 原因卡）、待处理队列、门控流水与回传批次、冲突裁决、追溯审计。

## 预置演示路径

- `XK-...001` A-01 正常许可：刷卡进入 → 新发第二组自动排队 → 离开后自动放行
- `XK-...003` 携带 09:00 到期物料：点「推进 70 分钟」后刷卡 → 物料过期停在外门
- `XK-...004` 携带已作废批次物料 → 批次作废拦截
- B-02 自带未结异常 → 刷卡排队，关闭异常后放行
- 断开门控 → 刷卡/改备注，中央端再改同一备注 → 恢复链路 → 回传出现冲突裁决
- 打开「回传链路中断」再点回传 → 批次失败；恢复后重试，仅补未确认流水
